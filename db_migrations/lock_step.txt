# Manifiesto lock-step de migraciones Postgres ↔ SQLite (ADR-002 §5).
#
# Toda migración que toca tablas sincronizables (members, payments,
# memberships, etc.) tiene que vivir en LOS DOS motores en paralelo —
# sin esto, un sidecar nuevo y un cloud nuevo dejan de hablar el mismo
# wire format y rompen sync. Este manifiesto materializa el pareo.
#
# Formato: una línea por par o por migración cloud-only.
#
#   pair: pg=NNN_filename sqlite=MMM_filename   (la migración existe en
#                                                ambos motores; los
#                                                números pueden diferir
#                                                porque postgres y sqlite
#                                                tienen secuencias
#                                                independientes)
#
#   cloud_only: pg=NNN_filename reason="…"      (la migración NO existe
#                                                en SQLite porque toca
#                                                tablas que sólo viven
#                                                en el cloud — sidecar_
#                                                credentials, installer_
#                                                bootstraps, email_
#                                                verification, etc. El
#                                                reason: explica por qué)
#
# Lockstep check (scripts/check_lockstep.sh, corre en CI) parsea este
# archivo y valida:
#
#   1. Cada archivo en db_migrations/postgres/*.sql está listado acá
#      como pair: o cloud_only:.
#   2. Cada archivo en db_migrations/sqlite/*.sql aparece en una línea
#      pair: (no hay sqlite_only — el cloud SIEMPRE manda).
#   3. Cada pair: referencia archivos que existen en disco.
#
# Si alguien agrega una migración nueva sin actualizar este manifiesto,
# el CI falla y bloquea el merge. Honor system + safety net.
